Self-hosted by design

The Lockfile is meant to run on infrastructure you control. Repository contents, scan results, findings, and account data stay with your deployment unless you choose to send them elsewhere.

What this instance may store

  • Account credentials and session data for people who sign in
  • Repository metadata you connect (names, IDs, visibility)
  • Scan jobs and findings produced by scanners
  • Operational logs written by Django, Celery, and your host

GitHub access

When a GitHub App is connected, access follows GitHub's normal permission model for the installation you approve. The Lockfile does not require sending repo data to thelockfile.com to function.

Cookies and sessions

Signed-in use relies on session cookies for authentication. There is no third-party advertising tracker in this application shell.

Operators

Whoever runs this instance is responsible for their own retention, access control, backups, and disclosure practices. Update this page for your organization as needed.
