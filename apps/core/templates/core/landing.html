The Lockfile

Know what's inside your code.

Run it on your own servers. It checks GitHub repos for secrets, bad dependency versions, weak config, and gaps in how you ship code.

  • critical Hardcoded secret in .env.local
  • high Known CVE in a lockfile dependency
  • medium Branch protection not enabled
  • low Base image tag is floating

What it finds

Each finding includes a short explanation and a concrete fix. You do not need a security background to act on most of them.

  • Exposed secrets

    Keys and tokens that ended up in the repo or git history.

  • Vulnerable dependencies

    Known CVEs and old packages in manifests and lockfiles.

  • Insecure configs

    Risky defaults in CI, Docker, cloud, and app config files.

  • Missing practices

    Things like branch protection and required reviews that are not set.

  • Workflow gaps

    Places where code can reach production without enough checks.

  • Plain-language reports

    What was found, why it matters, and what to change.

Why self-hosted

Code, scan results, and reports stay on machines you run. Install a GitHub App, choose repos, and scan. Nothing is required to leave your network for the product to work.

Public and private repos both work. Private access uses GitHub permissions the same way other GitHub Apps do. 

# stack
docker compose up --build

# data
postgres, redis, local volumes

# repos
GitHub App -> select -> scan

How it works

Three steps to get from a blank host to your first findings.

  1. Step 1

    Install and run

    Start The Lockfile with Docker Compose on your hosts.

  2. Step 2

    Connect GitHub

    Install the GitHub App and pick the repos to scan.

  3. Step 3

    Review findings

    Read the report, make the changes, and move on.
