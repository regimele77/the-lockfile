What it finds

Clear findings with explanations and recommendations — so your team can fix issues without becoming a security team overnight.

  • Exposed secrets

    API keys, tokens, and credentials that slipped into the tree or history.

  • Vulnerable dependencies

    Known CVEs and outdated packages across lockfiles and manifests.

  • Insecure configs

    Risky defaults in CI, Docker, cloud, and app configuration.

  • Missing practices

    Branch protection, review rules, and other hygiene that quietly erodes.

  • Workflow weak spots

    Gaps in how code moves from pull request to production.

  • Actionable reports

    Every finding explains why it matters and what to do next.

Why self-hosted

Repo data, scan results, and reports stay on your infrastructure. You connect a GitHub App, pick which repositories to scan, and keep control of the pipeline end to end.

Public and private repos are supported. Private access uses GitHub's normal permission model — nothing exotic, nothing opaque. 

# your stack
docker compose up --build

# your data
postgres · redis · local volumes

# your repos
GitHub App → select → scan

How it works

Three steps from empty server to first findings.

  1. Step 1

    Install & run

    Bring up The Lockfile with Docker Compose on your own hosts.

  2. Step 2

    Connect GitHub

    Install the GitHub App and choose the repositories you want scanned.

  3. Step 3

    Review findings

    Read explanations, apply recommendations, and keep shipping with eyes open.
